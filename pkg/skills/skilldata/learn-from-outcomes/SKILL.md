# learn-from-outcomes

Relevance: learn, outcome, retrospective, why rejected, pattern, improve.

Post-outcome learning. Observations advisory; hard constraints untouched.

## Inputs

- opportunity/application id + outcome + optional note

## Procedure

1. record_opportunity_outcome with outcome + note.
2. Compare against evaluation: was the mismatch foreseeable (skill, evidence, compensation, client signals, timing)?
3. search_learned_preferences for existing related patterns; avoid duplicates.
4. record_learned_observation for genuinely new patterns ("repeatedly rejects X-heavy work").
5. If a hard-constraint change is implied (e.g. raise minimum), present it as a proposal for the user — never apply silently.

## Tools

record_opportunity_outcome, search_learned_preferences, record_learned_observation, search_application_history.

## Failure modes

- Single data point → note it, don't generalize.

## Approval

Recording only. Constraint changes need explicit user confirmation.
